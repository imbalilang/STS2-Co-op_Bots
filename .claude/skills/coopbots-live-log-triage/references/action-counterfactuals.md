# 从玩家观察追到可复验的决策错误

适用于用户举出具体动作、要求同样检查其他席位，或模型分数与实际机制矛盾的复盘。伤害排名只用于定位调查位置。低输出可能是防御或支援；最高输出席位也可能存在严重失误。

## 同一现场的动作对照

对每个被判错的席位，记录：回合与动作前快照、手牌及费用、能量、相关能力/遗物、敌方状态与意图、已执行动作、实际选择。用同版本 DLL 在同一起点执行合法替代动作；不能重新洗出更好手牌或用终局牌组替代当时牌组。

优先检查可明确比较的机会：结束回合时剩余可用资源、零费输出/生成链、抽牌发生在费用耗尽之后、禁止抽牌的前后顺序、弃牌/消耗选择破坏终端。先保留已经发生的动作，再比较剩余可做的动作；需要改动前缀时明确标出。

报告实际路线与替代路线各自的伤害、格挡、消耗资源、持久状态和死亡时点。少几层易伤等代价不能隐藏；“多打伤害”“撑过崩解”“撑过整个敌方回合”“整场获胜”是不同结论。说明隐藏字段/RNG是否完整恢复。局部重建的结算HP不能冒充实机后续HP。

## 先问好动作在哪一层丢失

1. 原生效果能否执行：检查合法性和真实结果，尤其升级、自动打牌、选择数量不足、多人触发。
2. 候选是否真的进入比较：记录候选路径和分数，不能从最终未选推断“没搜到”。
3. 被评分淘汰时拆项：即时伤害/生存、未来能力/减益、消耗保留、支付成本分别比较。
4. 比较器是否被调用：诊断入口能找出收益，但实盘没有比较日志，应追踪短路分支、旧胜利标记和剧本执行，而不是再给卡加分。

若多个席位在同一回合出现相同模式（例如各打三张就停），检查是否是模拟状态共同施加的限制。对齐敌方阶段、回合开始和强制选择：预测选项、实盘选项、选择后能力、出牌限制及后续边界。选择扣血未必错误；模拟选择限牌、实盘选择扣血后仍信任旧胜利结论才是另一类错误。

后台“启动/完成/采用”分别计数，再检查采用是否真正更优。遇到边界差异，确认丢弃的是后台候选、前台后续，还是仅撤销终局置信。预算增加不能解释为策略质量提高。

## 跨席位找同形失误

用户只报一个席位时，不要只复述它；用同一套模式扫其余席位。

1. 解析 `CoopBots order:`，给每条记录带上“战斗序号 + round”，不要只按 `round=` 分组——不同战斗会重复 round 1/2/3。战斗序号可在 `Creating NCombatRoom` 处递增。
2. 对每个席位找“同一战斗同一 round、手里已有 setup，却先打 payoff”的序列。CoopBots 的实例：
   - `BULLY` 先于 `BREAK/BASH/UPPERCUT/THUNDERCLAP/TREMBLE`（易伤加成损失）；
   - `SHIV/FAN_OF_KNIVES` 先于 `ACCURACY`（小刀加成损失）；
   - `BACKFLIP/DEFEND_SILENT/BLUR` 先于 `FADE/FOOTWORK`（临时敏捷损失）。
3. 用 DamageMeter 的按牌伤害聚合（逐 segment 的 `players[*].dbc` 求和）判断这是出牌错误还是构筑结果：
   - 最高伤害牌是 `STRIKE_*`：优先查 draft/牌组膨胀；
   - 最高伤害牌是单一 payoff：优先查 setup 牌序、强化、附魔；
   - 总伤最高只说明拿到了更强的牌，不说明决策更好。
4. 同一形状在多席位复现时，优先查生产搜索路径的共同开关（如 `SequenceLookahead` 在 reference job 是否开启），不要逐席改牌名规则。

## 分数反常时查数学含义

- 抽牌升级：列出升级前后的普通、长战无干扰、各干扰场景和合成项。若受干扰表现改善仍降分，检查是否减掉了改善更多的无干扰基线，或主项与罚项使用了不同战斗窗口。
- 未来收益：同起点只多造成少量伤害，其他状态相同时检查总分单调性。`ceil(敌HP/每轮输出)` 的回合跳变可能将已兑现伤害算成损失未来易伤价值。只在没有敌方阈值/换形等真实副作用时提出单调性要求。固定比较窗口时仍须保留新力量等真实状态收益；用“额外伤害不反降”和“新力量能放大后续易伤伤害”两个方向同时验证，避免修正窗口却抹掉投资收益。
- 高费用或复杂奖励：查真实支付机制，而非只看印刷费用；包含全队消耗降费、X费自动出牌、团队减伤。coverage标签不能证明关键收益已进入构筑模型。先验、稀释、能耗处罚也要单独列出。
- 商店：检查是否枚举删牌、收益到金币的换算、价格门槛、余额影响、第二件商品后的余额。区分未建模、已建模零收益、负收益；它们不能共用一个零分解释。
- 重复拿牌：从历史重建每次奖励之前的卡组，列出同次其他候选和跳过，拆开实际战斗增量与社区先验。不能因为重复张数多就直接判错，也不能让首张牌的通用推荐分反复掩盖后续副本的负收益。注意同层的商店、事件或多次奖励可能混在一条历史记录中；无法还原分组时只报告候选估值，不伪称完成了当时三选一重放。

把本场机制做成可故意破坏的回归。不要把某次观察固化成“抽牌永远先打”“金卡一律拿”“惩罚永远选扣血”等卡名规则；用户明确要求的路线/消费政策另行登记。
