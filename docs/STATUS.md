## 已知问题

五局中的第 1、2、3、5 局仍有具名状态差异。涉及牌来源标记、持续时间边界、生命周期缓存等；部分 Boss 续演还会因资格或物理牌引用失效被丢弃。它们对本批团灭的具体贡献尚未证明，也没有足够原生证据将其一概豁免为无害差异。

第 4 局有回合开始选牌预测无法自动应答的诊断和续演资格不足，不能仅由这些日志认定实机选牌失败。应先保存实际菜单、原生答案和后继状态，再判断属于预测覆盖还是执行缺陷。

当前尚未证明全 Bot A10 **50%** 整塔通关目标，混合桌也需要单独验收。全 Bot 改善不能直接外推到有真人持续改变盘面的桌面。

## 欢迎贡献

1. **模拟与执行一致性**：将具名差异收缩为原生短场景，对照真实游戏动作；修复后保留跨回合、父子分支与物理牌身份验证。避免通过删除状态检查掩盖未解释差异。
2. **固定成本下的有效搜索**：提高可用候选覆盖、减少无效续演和重复捕获，记录主线程延迟、分配、GC 与超时；四席共享既有决策预算，High 并发基线为 6。
3. **长战斗与团队防御**：结合席位生存、Boss 压力、药水时机与有效出牌顺序验证收益。真实原生盘面和相同预算对照优先于孤立评分。
4. **局外构筑**：检查资源启动、持续输出、防御、升级、删牌和事件选择，用完整爬塔战损及终局检验局部估值变化。
5. **混合桌失效处理**：真人输入后的取消、重新捕获、合同复核与响应成本，独立于全 Bot 统计。

本轮基线保持路线选择、既有搜索预算及知识恶魔统一瓦解。改变这些基线的实验须明确单独标识，避免把额外搜索资源当作算法提升。

## 如何提交可比较结果

从 [贡献指南](../CONTRIBUTING.md) 与 [测试指南](TESTING_AND_BENCHMARKS.md) 开始。登记候选源码/双 DLL/游戏/依赖身份、固定性能设置和开发/留出种子；保留每次尝试，包括卡死与异常。先在开发集定位，冻结候选后测试预先登记的留出集。公布实际样本、失败分母与区间，不能用单局或 5/10 宣称总体达标。
