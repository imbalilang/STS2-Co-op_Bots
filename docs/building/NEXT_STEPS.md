## 一、阶段 A：形式化指标与结果状态，固定当前配置的确定性复现并归档证据

**目的：** 在扩大任何样本之前，先把「一次运行算成功还是失败」「一个读数属于哪种结局」定义清楚，并证明当前配置可复现。

### A1. 形式化指标与结果状态

- 定义统一的结果状态枚举，至少覆盖：`完成-胜利`、`完成-失败`、`失败(异常)`、`超时`、`截断(fightTruncated)`、`无产物`。
- 明确每种状态**进入统计 / 单列 / 丢弃**的规则；`fightTruncated` 与 `fightWallMs` 必须参与分类，不得静默并入均值。
- 统一主/副指标与符号约定：暂时保留 `final_enemy_hp`（越低越好）用于兼容历史读数，同时记录 `finishedTurn` / `clear` / `hplost`。训练主目标与标签定义须由 Astra 审核，逐项声明方向，不能把所有指标都标成越低越好。
- 处理**胜利地板效应**：通关样本 `final_enemy_hp = 0`，需要时用副指标或分层来区分低损/高损通关，而不是让所有胜利塌成一个点。

**受影响文件（建议，需 Astra 确认）：**
- `scripts/soulnexus-sigma.py`（结果解析与 `describe`）
- `scripts/shiv-pm-interaction.py`（`run_one` / `summarize`）
- 新增结果状态定义与被测函数单元测试（位置由 Astra 指定）

### A2. 当前配置的确定性复现与证据归档【准备工具】

- 按**当前 4000ms 软预算配置**重验单独与并发重复性（早期纯节点预算的证明不覆盖本配置，见 `BASELINE.md` §四.5）。
- 复现「同种子、同牌组、同配置」重复多次逐位一致，以及并发下是否保持。
- 归档证据：固定配置、随机种子、请求/产物、哈希。使用已就绪的
  **[`scripts/capture-research-baseline.py`](../../scripts/capture-research-baseline.py)**（固定白名单快照 + SHA256 清单，不执行实验、不提交）。该工具不自动收录每次新实验；实验驱动另需在新目录保存完整配置、种子、请求、产物与清单。
- 用 **[`scripts/verify-project.ps1`](../../scripts/verify-project.ps1)** 生成独立日志的构建/类型加载/PatchSmoke 回归证据（写入 `work/verification/<UTC>/`，不碰 `outputs/`）。

### A 阶段验收条件（缺一不可）

1. 结果状态分类在**代码中可执行、在报告中有计数**；`fightTruncated` / 超时 / 异常不再进入或污染均值。
2. 主副指标与符号约定在脚本输出和文档中各只有一种写法。
3. 当前 4000ms 配置下，重复性试验给出**可复算的逐位一致/不一致结论**（是就是，不是就不是；不达标也照实报）。
4. `capture-research-baseline.py` 产出快照与清单（含 HEAD、dirty 状态）；`verify-project.ps1` 产出 `summary.json`（含 DLL SHA256、阶段退出码与日志）。
5. 以上证据交 Astra 复核；**未通过前不得进入阶段 B 的正式重设计采样**。

## 二、阶段 B：配对析因重设计（跨牌组、跨遭遇重复）

**目的：** 在正交化设计下重新检验 P×M，并利用固定种子的配对结构。

### B1. 设计约束（针对已知混淆）

- **不得移除不同数量的防御牌**：`REMOVAL_POOL` 里全是 `DEFEND_SILENT`，加 3 张生成器等于拿走 3 张格挡，P 与格挡共线（`BASELINE.md` §八.1）。改用不改变防御能力的冗余层，或把「移除」设为**独立因子**显式建模。
- **显式定义估计量**：区分「加牌(add)」与「替换(substitution)」——两者的问题不同（固定张数会让它们互相绑定），报告中必须写明本次估计的是哪一个。
- **控制牌组体积稀释**：不同格子的张数/构成必须可比，或把体积作为协变量/因子。
- **加入对照格**：至少包含「加一张中性牌」或「加一张死牌」的对照，用于检出与机制不符的格（如无 Shiv 时 ACCURACY 的 `P0M1`）。
- **符号与方向**：预注册必须写清主指标方向（越低越好）与交互项判定阈值，避免收益方向/原始方向混用（`BASELINE.md` §三）。

### B2. 统计与重复

- 直接统计**每种子的四格交互差**（配对），报告配对 CI；不再用「各格 sd 均值」近似独立样本标准误。
- 区分效应、随机方差与搜索预算偏差；预算（`budget_ms`）固定并记录，换预算视为换配置。
- 跨**多副牌组**与**多个遭遇**重复，避免单底座（`9f0f93ff71`）与单遭遇（SoulNexusElite）上的结论被外推。

**受影响文件（建议，需 Astra 确认）：**
- `scripts/shiv-pm-interaction.py`（移除池、附加因子、配对统计、预注册）
- 视需要新增设计/统计脚本（由 Astra 指派，不预先改名或移动既有脚本）
- 原始数据只读，不覆盖 `work/oracle/shiv-pm/pm.json`；新实验写入新目录

### B 阶段验收条件

1. 预注册（问题、因子、方向、判定阈值、移除策略）在采样前写入并被 Astra 确认。
2. 移除不再与防御能力共线；报告能分离「加/替换」估计量，并有中性/死牌对照。
3. 交互项按配对逐种子差给出，附配对 CI 与每格 `n`。
4. 至少在 >1 副牌组与 >1 个遭遇上重复，报告分层结果。
5. 明确结论只针对本次配置、底座与遭遇，不外推。

## 三、阶段 C：拟合 S(deck) 与有限差分（仅在仪器过关之后）

**进入前提：阶段 A 和直接选牌试验通过。** 阶段 B 只在需要解释特定协同时开展；不要求先证明全局乘法形状。

- 只在**仪器 gates 通过**后生成训练标签；先明确标签由哪个指标、哪种结果状态、哪种配置产生。
- 拟合目标为 `S(deck)`；有限差分只用于在**同一底座与配置**下估计局部变化，不替代对总指标的直接测量。
- **按整副牌组分组留出（grouped holdout by deck）**，禁止同副牌的样本跨训练/留出集。
- **必须与基线对比**：当前 `BuildValue.Deck`（`src/CoopBots/Building/BuildValue.cs:188`）以及简单基线（如加性单卡评分、牌组角色特征回归）。还需比较 `Add` / `Remove` / `UpgradeDelta` 的实际决策，报告增益符号、跳过判断与决策损失，不能只比较总分拟合误差。
- 明确 **OOD 回退**：未见过的角色/资源/模组卡上 `S(deck)` 的行为，必须有保守回退，不得静默给高分。
- 报告诚实边界：样本量、CI、留出误差、失效场景；**不承诺**达到某个具体 HP 精度或性能。

**受影响文件（建议，待 Astra 指派）：** 新增拟合/评估脚本与分析文档；生产算法在拟合通过 A/B 之前**不改动**。

### C 阶段验收条件

1. 标签生成可复算，并绑定明确的配置与结果状态规则。
2. 留出按牌组分组；报告训练/留出切分与泄漏检查。
3. `S(deck)` 与 `BuildValue`、简单基线同台比较，给出分层结果与 OOD 回退行为。
4. 结论包含明确的适用边界与不适用场景。
